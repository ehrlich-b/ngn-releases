## The change — one line, same shape as T12 and T19

LMP's gate reads `!isPV`, so it already exempts *true* PV nodes but not nodes that were PV in an earlier
iteration. `nodeTTPv` (= `isPV || (ttHit && ttPvEntry)`) is **already in scope** at that site. The candidate:

```go
-  if SearchToggles.LMP && !isPV && !inCheck && ...
+  if SearchToggles.LMP && !nodeTTPv && !inCheck && ...
```

## The argument — and it is stronger than "do more of what worked"

**LMR errors are partially SELF-CORRECTING; LMP errors are SILENT AND PERMANENT.** A wrongly-reduced move
that nevertheless beats alpha triggers a re-search, so the search gets a second chance at it. A
late-move-pruned move is **never looked at** — there is no re-search path, and nothing in the node records
that a move was skipped.

So the two prunes are not equally risky, and the asymmetry runs the wrong way relative to how NGN protects
them: **the mechanism with the recoverable failure mode already has ttPv protection (T19, +7.3); the
mechanism with the unrecoverable failure mode does not.** LMP is also the *most* speculative prune in the
engine — a pure move-count cutoff carrying **no per-move evidence at all**, unlike futility (compares a
margin), SEE pruning (an exact material computation) or history pruning (a learned statistic).

**This is a mechanism-level change, not a constant tweak** — the distinction that has now separated keeps
from misses four times this session (T12 soundness +2.2 and T19 structural mark +7.3 kept; T15 convention
symmetry -4.7 and T4e coarse learned key -20.9 shelved).

abandoning the ttPv-protection idea, which T19 already validated.**
