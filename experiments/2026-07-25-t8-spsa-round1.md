## (b) Game budget and the K choice

`playBatch` (cmd/spsa/main.go:175-190) plays **2 games per perturbation** (theta+ as White, then as Black —
color-balanced), run sequentially inside each worker. So **games/iter = 2K** and **concurrent games = K**.

`-pairs 8` is chosen so K matches the box's validated **c8** profile: 8 concurrent games = 16 engine
processes on 8c/16t, the exact topology the 961 g/hr baseline and the M5 adjudication A/A were measured on.
K=4 (the figure in the old queue text) would idle half the box and double wall-clock for the same games —
that number was written when the plan was 5+0.05, which **M6 did not enable** (A/A penta -8.3 [-20,+4] was
too lopsided), so this runs at 10+0.1 like every other gate on this rig.

**1500 iters x 2 x 8 = 24000 games**, clearing the >= 20k policy floor, ~25h at 961 g/hr. That buys 1500 theta
updates for 13 dims, which is thin — hence **round 1**: the deliverable is a partially-converged vector to be
gated, not a finished tune. Round 2 refines from the checkpoint if round 1's gate passes.
