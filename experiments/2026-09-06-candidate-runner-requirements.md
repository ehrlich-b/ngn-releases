Candidate match runner requirements, 2026-09-06

The corrected 200-game B0 A/A control is accepted. Its fixed runner and auditor stay frozen. A separate candidate wrapper will reuse the independently checked legality/terminal auditor and add explicit role identities, process supervision, and operational-error rejection. This document defines implementation scope; it does not authorize a timed match without a frozen concrete manifest.

Each run binds two binary SHA-256 identities, source/build provenance, ordered UCI options, per-role environment, requested/effective threads, total Hash, evaluator backend, and any network SHA-256. Copy binaries and networks into immutable run inputs and use separate initially empty engine working directories. Preserve the complete opening histories, paired colors, all moves, PGN, final EPD, engine trace, command/environment receipts and independent natural-terminal audit. No book, tablebase, ponder, resignation, recovery or draw/resign adjudication. Only validated supported options are sent. Startup and option application must be verified through sequential UCI/isready exchanges; NGN selected evaluation diagnostics verify the requested backend.

The existing fastchess -use-affinity implementation pins each game to one CPU. Retain that only for one-thread versus one-thread concurrent tests. Initial SMP tests use concurrency 1 under an explicit physical-core set with no -use-affinity, so both alternating roles can use their allocated cores. Record actual child /proc CPU masks and GOMAXPROCS, and reject mismatches. For 8v1 equal-time scaling, expose the same eight physical cores to both roles with explicit per-role Threads and GOMAXPROCS. Do not divide total Hash by worker count. Coordinate an otherwise idle machine for timed comparisons. Multiple c1 instances with disjoint groups can be added later after proving their affinity.

The wrapper must reject operational failures even when fastchess exits zero and an engine recovers with a legal bestmove. Reject canonical NGN info string error, panic/crash recovery, unknown/rejected required options, network-load errors, stall/timeout/disconnect, illegal PV/move and non-natural result reasons. Parse actual engine trace syntax; test error-plus-legal-fallback and error-plus-natural-game negative fixtures. Exact reviewed benign opponent startup messages may be allowed by pinned engine profile. Never blanket-allow stderr. Inspect crash logs by content, recognizing NGN's harmless crash-handler initialization separately from actual failures.

Every launched stage has a wall-time limit and process-group/observed-descendant supervision, including the auditor. Terminate, escalate, reap, and verify no survivors on error, timeout or interruption. Preserve partial logs and failure receipts. Do not rely on a process-name-only quiet check. Verify input hashes before execution, record actual loaded copies, and hash final artifacts after processes are terminal. A durable terminal record must be written on all failure paths.

Test in stages: deterministic manifest/option/affinity/error-parser negative fixtures; sequential UCI preflight for both roles; a tiny full-game operational smoke with independent audit; then a frozen diagnostic or strength manifest. The diagnostic pilot network does not need to beat HCE to justify a larger, verified corpus. Never relabel a diagnostic after seeing results. Predeclare game count or SPRT bounds, openings, time control, resource use, score confidence method and failure handling. For statistical analysis preserve opening pairs and report pair outcomes; no independent-game error bars for paired openings.

Move Overhead is a comparison parameter: historical B0 was sent 100 but ignored it and used 50 internally. Use 50 on the new engine when isolating evaluator/search changes against that baseline, or explicitly declare the timing-policy change. New-code HCE versus NNUE may use the same declared effective value.

Initial deliverable should be a small explicit JSON manifest schema and separate run_candidate_match.py with reviewed supporting modules/tests. Reuse accepted source by pinned copy/import; do not silently edit the frozen A/A runner or auditor. Keep human-facing configuration focused on engine, network, threads, time control and experiment purpose.
